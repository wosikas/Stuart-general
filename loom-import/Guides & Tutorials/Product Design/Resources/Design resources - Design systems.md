# Design resources - Design systems

Part of [[11 Resource library]] in the [[Product Design Prompt Kit]].

How mature teams define components and tokens, and the component libraries AI tools build with. Borrow their names and their rules.

32 links. A star marks an essential. Last link check: 18 November 2026.

- **[GOV.UK Design System](https://design-system.service.gov.uk/)** ★ (UK Government Digital Service; guideline; free). Every component and pattern comes with the research behind it. The best example of plain, accessible, tested design. *In a prompt:* "Use the GOV.UK 'one thing per page' pattern for this multi-step form."
- **[shadcn/ui](https://ui.shadcn.com/)** ★ (shadcn; kit; free). The component set most AI builders reach for by default. Knowing its component names lets you ask for them directly. *In a prompt:* "Build with shadcn/ui: Sheet, Command, Toast and Skeleton. No custom components."
- **[The Component Gallery](https://component.gallery/)** ★ (Iain Bean; reference; free). Every common component, what it is called in each major design system, and links to all their versions. Invaluable for naming things. *In a prompt:* "What do the major design systems call this pattern, and how do they handle it?"
- **[IBM Carbon](https://www.carbondesignsystem.com/)** (IBM; guideline; free). A rigorous enterprise system. Especially good on data tables, forms and dense layouts. *In a prompt:* "Use Carbon's data table patterns: sorting, batch actions and inline edit."
- **[Atlassian Design System](https://atlassian.design/)** (Atlassian; guideline; free). Clear foundations for tokens, spacing and colour roles, with good writing on naming. *In a prompt:* "Name colour tokens by role, the way Atlassian does, not by hue."
- **[Adobe Spectrum](https://spectrum.adobe.com/)** (Adobe; guideline; free). A system built for creative tools. Good on colour, density scales and complex controls. *In a prompt:* "Offer medium and large scale variants, as Spectrum does for touch."
- **[GitHub Primer](https://primer.style/)** (GitHub; guideline; free). A developer-tool system with thoughtful UI patterns for lists, navigation and saving. *In a prompt:* "Follow Primer's guidance on saving patterns: explicit save versus autosave."
- **[U.S. Web Design System](https://designsystem.digital.gov/)** (U.S. General Services Administration; guideline; free). Accessible components and design principles with usability guidance on each one. *In a prompt:* "Use USWDS form guidance: labels above fields, hints, and error placement."
- **[Radix Primitives](https://www.radix-ui.com/primitives)** (WorkOS; kit; free). Unstyled, accessible building blocks that shadcn/ui sits on. The docs show correct keyboard behaviour for each. *In a prompt:* "Match the keyboard interaction Radix documents for this dropdown menu."
- **[Tailwind CSS](https://tailwindcss.com/)** (Tailwind Labs; tool; free). The utility CSS framework most AI builders output. Its default spacing, type and colour scales are a ready-made token set. *In a prompt:* "Use only Tailwind's default spacing scale; no arbitrary pixel values."
- **[Atomic Design](https://atomicdesign.bradfrost.com/table-of-contents/)** (Brad Frost; book; free). The book that gave design systems their vocabulary: atoms, molecules, organisms, templates, pages. Free to read online. *In a prompt:* "Break this screen into atoms, molecules and organisms, and name each."
- **[Design Tokens Community Group](https://www.designtokens.org/)** (W3C Community Group; reference; free). The emerging standard file format for design tokens, so tools and code can share them. *In a prompt:* "Output tokens in the Design Tokens Community Group JSON format."
- **[Material 3: Design tokens](https://m3.material.io/foundations/design-tokens/overview)** (Google; guideline; free). The clearest explanation of reference, system and component tokens, and why the layers matter. *In a prompt:* "Structure tokens in three tiers: reference, system and component."
- **[Design Systems Repo](https://designsystemsrepo.com/)** (Jad Limcaco; gallery; free). A directory of public design systems, plus articles and talks on building them. *In a prompt:* "Show me how three public design systems specify a toast."
- **[Design System Checklist](https://www.designsystemchecklist.com/)** (Arturo Ríos; reference; free). A checklist of everything a design system should define, from colour to tooling. *In a prompt:* "Which items on a design system checklist are we missing for v1?"
- **[Storybook](https://storybook.js.org/)** (Storybook; tool; free). The standard workshop for building and documenting components in isolation, one state at a time. *In a prompt:* "Write a Storybook story for every variant and state of this component."
- **[Open UI](https://open-ui.org/)** (W3C Community Group; reference; free). Research into how components behave across design systems, feeding new web standards. *In a prompt:* "What does Open UI's research say about how a combobox should behave?"
- **[Design Systems 101](https://www.nngroup.com/articles/design-systems-101/)** (NN/g; article; free). What a design system contains, who maintains it, and when building one is worth it. *In a prompt:* "Do we need a design system yet, or only a style guide and a component list?"
- **[Design Systems 101: What Is a Design System?](https://www.figma.com/blog/design-systems-101-what-is-a-design-system/)** (Figma; article; free). A clear introduction from the tool most systems are built in, with the vocabulary explained. *In a prompt:* "Explain the difference between a style guide, a component library and a design system."
- **[Interface Inventory](https://bradfrost.com/blog/post/interface-inventory/)** (Brad Frost; article; free). How to screenshot and sort every button, heading and form field you have, to expose inconsistency before building a system. *In a prompt:* "Audit this app: list every distinct button, heading and input style in use."
- **[Design System Resources](https://designsystems.surf/)** (Design Systems Surf; reference; free). A searchable directory of public design systems, with component-by-component comparisons. *In a prompt:* "Compare how three public design systems specify this component."
- **[Design Systems (book)](https://www.smashingmagazine.com/design-systems-book/)** (Alla Kholmatova · Smashing Magazine; book; paid). A practical book on functional and perceptual patterns, shared language and how real teams run their systems. *In a prompt:* "Name our functional patterns and our perceptual patterns separately."
- **[Guide to developer handoff in Figma](https://www.figma.com/best-practices/guide-to-developer-handoff/)** (Figma; guideline; free). What developers need from a design file: organisation, annotations, states and specs. *In a prompt:* "Organise this handoff the way a well-prepared Figma file would be."
- **[MUI](https://mui.com/)** (MUI; kit; free tier). The most widely used React component library, implementing Material Design. *In a prompt:* "Build with MUI components and its default theme; no custom CSS."
- **[Ant Design](https://ant.design/)** (Ant Group; kit; free). A complete enterprise component library with strong tables, forms and data entry. *In a prompt:* "Use Ant Design for this admin screen: Table, Form and Drawer."
- **[Chakra UI](https://chakra-ui.com/)** (Chakra UI; kit; free). An accessible React component library with a simple token-based styling system. *In a prompt:* "Build with Chakra UI and define the theme tokens first."
- **[Mantine](https://mantine.dev/)** (Mantine; kit; free). A large React component and hooks library with good defaults and dark mode built in. *In a prompt:* "Use Mantine components with its built-in dark colour scheme."
- **[Headless UI](https://headlessui.com/)** (Tailwind Labs; kit; free). Unstyled, accessible components designed to pair with Tailwind. *In a prompt:* "Use Headless UI for behaviour and style it entirely with our tokens."
- **[React Aria](https://react-aria.adobe.com/)** (Adobe; kit; free). Adobe's unstyled components with the most thorough accessibility and touch behaviour available. *In a prompt:* "Build on React Aria so keyboard, screen-reader and touch behaviour are correct."
- **[Base UI](https://base-ui.com/)** (Base UI; kit; free). Unstyled accessible components from the teams behind Radix and MUI. *In a prompt:* "Use Base UI primitives and apply our own visual design."
- **[daisyUI](https://daisyui.com/)** (daisyUI; kit; free). Ready-made component classes for Tailwind, with many themes. *In a prompt:* "Use daisyUI components with a custom theme of our colours."
- **[Untitled UI](https://www.untitledui.com/)** (Jordan Hughes; kit; free tier). A very large Figma UI kit and matching React library. A good neutral starting point. *In a prompt:* "Start from a neutral, well-structured kit and change only tokens."
