# Design resources - Platform guidelines

Part of [[11 Resource library]] in the [[Product Design Prompt Kit]].

The rulebooks for iOS, Android and the web, and the frameworks apps are built with. Name one in a prompt and the AI follows its conventions.

23 links. A star marks an essential. Last link check: 18 November 2026.

- **[Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/)** ★ (Apple; guideline; free). The rulebook for iOS, iPadOS and macOS. Read Foundations first, then the component page for whatever you are designing. *In a prompt:* "Follow Apple HIG for sheets: detents, grabber, and dismissal behaviour."
- **[Apple HIG: Patterns](https://developer.apple.com/design/human-interface-guidelines/patterns)** (Apple; guideline; free). Apple's guidance on whole behaviours: onboarding, searching, entering data, managing notifications, going full screen. *In a prompt:* "Design the first-run experience to match HIG onboarding guidance."
- **[Apple Design Resources](https://developer.apple.com/design/resources/)** (Apple; kit; free). Official Figma and Sketch UI kits, templates and fonts for every Apple platform. *In a prompt:* "Use components that exist in Apple's iOS UI kit before inventing custom ones."
- **[Apple design videos](https://developer.apple.com/videos/design/)** (Apple; video; free). WWDC design sessions. Search for 'Designing Fluid Interfaces' and 'Essential Design Principles'. *In a prompt:* "Apply the principles from Apple's Essential Design Principles talk to this flow."
- **[Material Design 3](https://m3.material.io/)** ★ (Google; guideline; free). The rulebook for Android and a strong general reference. Each component page has anatomy, specs and do/don't examples. *In a prompt:* "Use Material 3 components and tokens; cite the component spec you followed."
- **[Material 3: Components](https://m3.material.io/components)** (Google; guideline; free). Every Material component with usage guidance, measurements and accessibility notes. *In a prompt:* "Use a Material 3 modal bottom sheet and follow its spec for the drag handle."
- **[Android: design for mobile](https://developer.android.com/design/ui/mobile)** (Google; guideline; free). Android-specific layout, navigation, widgets and system behaviours such as edge-to-edge and predictive back. *In a prompt:* "Support Android edge-to-edge and predictive back in this layout."
- **[Fluent 2](https://fluent2.microsoft.design/)** (Microsoft; guideline; free). Microsoft's system for Windows, web and cross-platform apps. Strong on dense, productivity-style interfaces. *In a prompt:* "Use Fluent 2 patterns for this dense desktop table view."
- **[iOS vs. Android App UI Design: The Complete Guide](https://www.learnui.design/blog/ios-vs-android-app-ui-design-complete-guide.html)** ★ (Erik Kennedy; article; free). A side-by-side comparison of navigation, controls, typography and conventions on the two platforms. Expands the table in this kit. *In a prompt:* "List every place this iOS design must change to feel native on Android."
- **[Learn Responsive Design](https://web.dev/learn/design)** (Google · web.dev; course; free). A free course on layouts that adapt: media queries, fluid type, responsive images and interaction differences. *In a prompt:* "Make this layout fluid between breakpoints, not just fixed at three sizes."
- **[Responsive Web Design](https://alistapart.com/article/responsive-web-design/)** (Ethan Marcotte · A List Apart; article; free). The 2010 article that named the idea. Short, and still the clearest statement of why layouts should flex. *In a prompt:* "Design mobile-first, then enhance for wider screens."
- **[Web Interface Guidelines](https://vercel.com/design/guidelines)** (Vercel; guideline; free). A terse, opinionated checklist of details that make web interfaces feel good: focus, forms, loading, motion and touch. *In a prompt:* "Audit this web UI against Vercel's Web Interface Guidelines."
- **[How Do Users Really Hold Mobile Devices?](https://www.uxmatters.com/mt/archives/2013/02/how-do-users-really-hold-mobile-devices.php)** (Steven Hoober · UXmatters; article; free). The field study behind the thumb zone: how people actually grip and touch their phones. *In a prompt:* "Place the three most frequent actions where a one-handed thumb reaches."
- **[Mobile UX: study guide](https://www.nngroup.com/articles/mobile-ux-study-guide/)** (NN/g; reference; free). An index of NN/g's mobile articles and videos, grouped by topic. *In a prompt:* "Follow NN/g mobile guidance for this form: input types, labels and keyboards."
- **[Apple HIG: Layout](https://developer.apple.com/design/human-interface-guidelines/layout)** (Apple; guideline; free). Safe areas, margins, alignment and adapting to every device size on Apple platforms. *In a prompt:* "Respect safe areas and system margins on every iPhone size."
- **[Apple HIG: Typography](https://developer.apple.com/design/human-interface-guidelines/typography)** (Apple; guideline; free). The built-in text styles, their sizes at each Dynamic Type setting, and minimum sizes. *In a prompt:* "Use the built-in text styles, such as Body and Headline, so text scales with Dynamic Type."
- **[Apple HIG: Color](https://developer.apple.com/design/human-interface-guidelines/color)** (Apple; guideline; free). System colours, semantic colours that adapt to light and dark, and contrast guidance. *In a prompt:* "Use semantic system colours so everything adapts to light, dark and increased contrast."
- **[Material 3: Typography](https://m3.material.io/styles/typography/overview)** (Google; guideline; free). The Material type scale: display, headline, title, body and label, each in three sizes. *In a prompt:* "Assign every text element a Material type role, such as title-medium or body-large."
- **[SwiftUI](https://developer.apple.com/swiftui/)** (Apple; tool; free). Apple's framework for building native interfaces. Knowing its component names lets you ask for native iOS screens precisely. *In a prompt:* "Build this natively in SwiftUI with standard components: NavigationStack, List, Sheet."
- **[Jetpack Compose](https://developer.android.com/compose)** (Google; tool; free). Android's modern native interface toolkit, with Material 3 components built in. *In a prompt:* "Build this in Jetpack Compose with Material 3 components."
- **[React Native](https://reactnative.dev/)** (Meta; tool; free). Builds iOS and Android apps from one codebase using native components. A common target for AI-built mobile apps. *In a prompt:* "Build this in React Native and follow each platform's native navigation."
- **[Expo](https://expo.dev/)** (Expo; tool; free tier). The standard toolkit for building, previewing and shipping React Native apps. Lets you try an AI-built app on your own phone quickly. *In a prompt:* "Set this up as an Expo app I can preview on my phone."
- **[Flutter](https://flutter.dev/)** (Google; tool; free). Google's toolkit for building apps for mobile, web and desktop from one codebase. *In a prompt:* "Build this in Flutter with Material 3 widgets, and Cupertino widgets on iOS."
